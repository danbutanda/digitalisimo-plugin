# Carruseles en WordPress Playground

Entorno individual: WordPress 7.1.3 según el HTML servido por Playground, PHP 8.2, Elementor gratuito 4.3.4, DIGITALÍSIMO Elements 4.3.0.17/18 y tema Twenty Twenty-Five. Se creó una página de prueba con `digitalisimo-brand-carousel` (una marca) y `digitalisimo-logo-carousel` (dos imágenes). El HTML final solicitó sólo `carousel-engine.css`, `brand-carousel.css`, `logo-carousel.css` y `carousel-engine.js`; la portada sin estos widgets no solicitó esos recursos. No aparecieron errores JavaScript.

Antes del ajuste, dos logotipos con cuatro columnas configuradas ocupaban 144.25 px cada uno dentro de un carrusel de 625 px, dejando espacio vacío. Después, cada uno ocupa 304.5 px a 1440 y 768 px de viewport. A 390 px, la tarjeta mide 310 px, el botón avanza 326 px y se deshabilita al llegar al final. Se inspeccionaron capturas en las tres anchuras; las imágenes y controles se muestran sin desbordamiento visible. El editor Elementor abrió la página de prueba, mostró ambos widgets y no registró errores JavaScript.

En otra ejecución de Playground se habilitó Multisite, se activó Elementor y Elements para la red y se creó `/sitio-dos/` (`blog_id` 2). El gestor de Elementor registró `digitalisimo-brand-carousel` y `digitalisimo-logo-carousel` en el sitio principal y después de `switch_to_blog(2)`; `home_url('/')` devolvió `http://localhost/sitio-dos/` en el segundo sitio. Esta prueba verifica registro de red y contexto de URL. No prueba todavía el render frontend del segundo sitio ni equivalencia visual con Element Pack.
