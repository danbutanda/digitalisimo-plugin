# Criterios de Schema de DIGITALÍSIMO SEO

El grafo se construye con los datos del sitio actual. En Multisite, cada sitio usa su propia URL, opciones heredadas y contenido. Una entidad `LocalBusiness` válida sustituye a `Organization` en la identidad principal porque es un subtipo de `Organization`; publicar ambas para el mismo negocio duplicaría la identidad.

- Toda URL pública conserva una identidad, `WebSite` y una página enlazados por `@id`. Las páginas internas con ruta real añaden `BreadcrumbList`.
- Las entradas de WordPress son `BlogPosting`. El editor puede declarar una página como `Article` o `Service`; un CPT llamado `service`, `services`, `servicio` o `servicios` se reconoce como servicio. `areaServed` procede sólo de una ubicación editorial vinculada. Una oferta de servicio sólo entra si una integración proporciona precio numérico y moneda ISO de tres letras mediante el filtro `digitalisimo_seo_service_offer`.
- Las páginas de producto de WooCommerce se declaran `Product`. Una oferta simple usa el precio que WooCommerce muestra y su moneda; si WooCommerce publica un schema más completo, la unificación conserva sus ofertas, variantes y reseñas. Con la unificación desactivada, WooCommerce conserva su propio `Product` y SEO no crea otro. Una página común con la opción editorial «Producto» no genera `Product` sin datos reales.
- Un único video local se declara `VideoObject` cuando el bloque de WordPress o widget de Elementor señala un adjunto de video con título, fecha de carga y miniatura reales. Si el archivo no aparece en un elemento `<video>` o `<source>` del HTML final, se retira. Videos externos sin esos datos se dejan al proveedor o al schema explícito.
- Un archivo público de autor se declara `ProfilePage` con `Person`. El editor permite marcar una página individual como perfil de persona. Los artículos reutilizan el mismo `@id` del autor.
- `FAQPage` se conserva sólo si cada pregunta y su respuesta aparecen en el texto del HTML público. Se clasifica como marcado semántico, no como resultado enriquecido vigente de Google.
- El auditor valida tipos y propiedades frente al vocabulario local de Schema.org, revisa los requisitos conocidos de Google y ofrece enlaces al validador oficial de Schema.org y a Rich Results Test. «Potencial» no garantiza que Google muestre una función.

Documentación oficial consultada: [Schema.org](https://schema.org/), [Article](https://developers.google.com/search/docs/appearance/structured-data/article), [Product](https://developers.google.com/search/docs/appearance/structured-data/product-snippet), [Video](https://developers.google.com/search/docs/appearance/structured-data/video), [ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page), [Organization](https://developers.google.com/search/docs/appearance/structured-data/organization), [LocalBusiness](https://developers.google.com/search/docs/appearance/structured-data/local-business) y [cambios de Google Search](https://developers.google.com/search/updates).
