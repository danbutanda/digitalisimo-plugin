# Roadmap de funcionalidades · Digitalisimo

Los objetivos activos de rendimiento de DIGITALÍSIMO SEO están en [PERFORMANCE_OBJECTIVE.md](PERFORMANCE_OBJECTIVE.md) y [PERFORMANCE_MULTISITE_OBJECTIVE.md](PERFORMANCE_MULTISITE_OBJECTIVE.md). SEO 1.0.150 amplía el diagnóstico de WooCommerce y muestra el origen de plugins terceros. El objetivo nuevo agrega un panel independiente y controles Multisite; la validación anterior todavía no está cerrada.
SEO 1.0.152 incorpora CSS diferido y técnico opt-in en sitio/red; ninguno se activa por defecto ni se considera validado visualmente sin un sitio de pruebas representativo.
SEO 1.0.153 añade inventario administrativo de Kit, CSS de fuentes locales y Custom Code de Elementor por sitio, sin bloqueo de fuentes ni cambios de tracking.
SEO 1.0.154 prepara GT/GA4/GTM opt-in con preflight de duplicados y modos de carga reversibles; la producción actual con Site Kit y Custom Code mantiene la salida de Digitalísimo bloqueada.
SEO 1.0.155 añade preloads WOFF2 locales opt-in por sitio/red, con inventario administrativo, CSS encolado obligatorio y protección frente a duplicados de WordPress y Custom Code. Sigue pendiente la prueba de red y fuentes en navegador.
SEO 1.0.156 agrega una preparación de migración desde Elementor Custom Code que sólo llena IDs y WOFF2 locales inequívocos en ajustes vacíos del sitio; mantiene las funciones apagadas y deja los fragmentos de Elementor intactos.
SEO 1.0.157 prepara blindaje optativo para CSS local de fuentes Elementor: crea copias por sitio al solicitarlo en administración, protege icon fonts y conserva el CSS original cuando la política o el archivo cambian. Sin validación visual real permanece apagado.

Leyenda: `✓` implementado, `~` parcial/en validación, `□` pendiente. La prioridad se ejecuta por lotes para mantener paquetes instalables.

Actualización SEO 1.0.127: las keywords objetivo quedan limitadas a una principal y hasta cuatro secundarias. La generación IA separa secundarias de la misma intención de las sugerencias SEO adicionales (términos semánticos, FAQs, oportunidades de contenido y nuevas páginas), sin inventar métricas de búsqueda. SEO → Avanzado incorpora un switch de optimización móvil, apagado por defecto, que evita el desplazamiento horizontal accidental sin afectar zoom, scroll vertical ni sliders. En Red → Digitalisimo → Clonar sitio, un superadministrador puede replicar un subsitio con sus tablas, medios, opciones, roles y URLs ajustadas al destino; el destino queda privado durante el proceso.

## Orden de ejecución pendiente

1. Completar crawlers, presets, robots efectivo y Multisite.
2. Completar auditoría, entidades, diagnóstico y score por URL.
3. Completar llms.txt e IndexNow.
4. Completar referencias IA y privacidad.
5. Completar embeddings opcionales y panel de conocimiento IA.
6. Validar en WordPress individual y Multisite, después generar paquetes versionados.

## Validación de paquetes

Última validación estructural: los ZIP de SEO 1.0.124, Ecommerce 1.0.17, Geolocalización 1.0.15, IA Tools 1.0.41 y Hosting 1.0.11 contienen su archivo principal, declaran la versión esperada y superan `unzip -t` y `tests/validate-suite.mjs`. El catálogo de ubicaciones se administra dentro de SEO como una taxonomía jerárquica independiente, evitando los flujos editoriales de entradas y sus errores de inserción; cualquier contenido público puede usarlo y ser pilar o secundario de un cluster. Las ubicaciones se editan y eliminan desde el mismo catálogo; al borrar una se limpian sus asignaciones para no dejar shortcodes con referencias rotas. `[ubicacion_seo]` se expresa desde zona hasta país y la ubicación elegida se emite en JSON-LD como `spatialCoverage` y, con SEO local activo, como `areaServed`. La columna Ubicación valida el término editorial y muestra su jerarquía desde la zona hasta el país, o marca el valor predeterminado aplicado. SEO Front compara el slug publicado por términos relevantes y no recomienda alterar la URL raíz de la portada, agrupa las keywords secundarias ausentes en una recomendación y muestra autor y publisher del HTML real. Las sugerencias IA de Keywords y descripción son acciones separadas: la descripción única se aplica a extracto y meta descripción, y la intención de búsqueda ya no se configura en cada contenido. La ficha verde identifica la keyword principal y sus fichas se reordenan por arrastre. La plantilla de alt predeterminado se aplica sólo al renderizar adjuntos que no tengan alt propio y admite variables de contenido, sitio, imagen y `%sep%`. Las instalaciones nuevas usan título de entrada `%title% %sep% %sitename%`; títulos de página y archivo `%title%`; y `%excerpt%` como descripción de entradas, páginas y archivos. La pantalla Títulos explica el valor público de cada variable disponible. Una migración única completa esas plantillas cuando una versión anterior las había guardado vacías y, al guardar, un campo vacío restaura su valor predeterminado. Los valores que coinciden con el predeterminado del plugin se muestran en gris y se identifican como tales. Nombre SEO e imágenes predeterminadas son siempre locales; la red usa el mismo componente de navegación del sitio y los valores heredados se ven en gris. Los bots que declaren ser Google o Bing se registran sin DNS durante la visita, se verifican por cola y los falsos pueden bloquearse manualmente por sitio. Las plantillas quedan excluidas. En Contenido → Configuración puede definirse un pilar predeterminado para contenidos nuevos, heredable en Multisite. Los selectores de la UI administrativa conservan una anchura compacta. Durante desarrollo, el verificador de Releases consulta GitHub cada minuto; al estabilizarse se regresará a una hora.
