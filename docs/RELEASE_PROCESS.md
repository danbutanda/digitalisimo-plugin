# Publicación de los plugins Digitalisimo

Los siete plugins se actualizan de forma independiente desde WordPress. Cada entrega de código debe incrementar la versión en el encabezado PHP y en `tests/validate-suite.mjs` **sólo de los módulos modificados**. Cada versión nueva debe superar la ya publicada para ese módulo.

Al enviar a `main` un cambio dentro de cualquiera de los siete directorios de plugins, `.github/workflows/release.yml` ejecuta la validación PHP y la suite completa, detecta qué módulos cambiaron, construye sólo sus ZIPs y compara sólo sus versiones contra los assets publicados. Si todo pasa, crea una Release con etiqueta numerada `vAAAA.MM.DD.N` que contiene exclusivamente los ZIPs de los plugins modificados. El número `N` es el número de ejecución del workflow. El workflow falla si falta un ZIP, sobra otro o una versión seleccionada no avanzó. También puede iniciarse manualmente desde GitHub Actions, indicando los slugs de los módulos a publicar separados por espacios.

Antes de dar la entrega por terminada, revisar que el workflow **Publicar módulos Digitalisimo** terminó correctamente y comprobar en la Release pública únicamente las versiones y ZIPs modificados. Los actualizadores de WordPress buscan el asset más reciente de su propio módulo entre las Releases, por lo que los plugins intactos no necesitan aparecer en cada una. WordPress detecta una actualización sólo cuando la versión publicada supera la instalada; la detección también depende de la próxima consulta de actualizaciones de WordPress. El primer paso de instalaciones con actualizadores antiguos puede requerir actualizar el ZIP una vez para incorporar el mecanismo `Update URI` nativo.

SEO 1.0.165 agrega una comprobación independiente cada cinco minutos con WP-Cron y actualiza el aviso de `update_plugins` sin esperar la caché horaria compartida. WP-Cron depende del tráfico o de un cron del servidor; una instalación todavía anterior a 1.0.165 conserva el comportamiento de su actualizador previo hasta instalar esa versión.

Para validar localmente la suite completa: `bash scripts/build-packages.sh /tmp/digitalisimo-suite` y `DIGITALISIMO_PACKAGE_DIR=/tmp/digitalisimo-suite node tests/validate-suite.mjs`. Para validar una publicación individual: `bash scripts/build-packages.sh /tmp/digitalisimo-release digitalisimo-tools` y `DIGITALISIMO_PACKAGE_DIR=/tmp/digitalisimo-release node scripts/verify-release.mjs --remote digitalisimo-tools`. Usar directorios vacíos para que los ZIPs históricos no se mezclen con una entrega nueva; conservar los anteriores en `rollback/`.
