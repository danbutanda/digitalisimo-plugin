# Publicación de los plugins Digitalisimo

Los seis plugins se actualizan de forma independiente desde WordPress. Cada entrega de código debe incrementar la versión en el encabezado PHP de **los seis módulos** y en `tests/validate-suite.mjs`. Las versiones nuevas deben superar a las ya publicadas en GitHub Releases.

Al enviar a `main` un cambio dentro de cualquiera de los seis directorios de plugins, `.github/workflows/release.yml` ejecuta la validación PHP, construye los ZIPs, ejecuta las pruebas y compara las seis versiones contra los assets publicados. Si todo pasa, crea una Release con etiqueta numerada `vAAAA.MM.DD.N` y exactamente estos assets: SEO, Ecommerce, IA Tools, Hosting, Backups y Tools. El número `N` es el número de ejecución del workflow. El workflow falla si falta un ZIP, sobra otro o una versión no avanzó. También puede iniciarse manualmente desde GitHub Actions si el código ya se envió a `main`.

Antes de dar la entrega por terminada, revisar que el workflow **Publicar módulos Digitalisimo** terminó correctamente y comprobar en la Release pública las seis versiones y sus ZIPs. WordPress detecta una actualización sólo cuando la versión publicada supera la instalada; la detección también depende de la próxima consulta de actualizaciones de WordPress. El primer paso de instalaciones con actualizadores antiguos puede requerir actualizar el ZIP una vez para incorporar el mecanismo `Update URI` nativo.

Para validar localmente: `bash scripts/build-packages.sh /tmp/digitalisimo-packages`, `DIGITALISIMO_PACKAGE_DIR=/tmp/digitalisimo-packages node tests/validate-suite.mjs` y `DIGITALISIMO_PACKAGE_DIR=/tmp/digitalisimo-packages node scripts/verify-release.mjs`. Usar un directorio vacío para que los ZIPs históricos no se mezclen con una entrega nueva; conservar los anteriores en `rollback/`.
